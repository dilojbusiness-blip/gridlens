The field guide

Rows can move.
The key stays
the connection.

Why a line diff struggles with reordered CSV rows—and when a literal keyed comparison is the right tool.

Try the example ↗

Text diff algorithms align similar lines while preserving their sequence. A moved CSV record can appear as a deletion and insertion; it is not necessarily paired with its matching identifier. CSV records can also span several physical lines when a quoted field contains a newline. A database export without explicit ordering or a re-sorted spreadsheet can shuffle records without changing their field values. Matching parsed records by a unique identifier makes those movements easier to separate from actual field changes.

A synthetic example

These two synthetic files contain the same products and values in a different order:

left.csv
id,name,price
id001,Widget,1
id002,Gadget,2.00

right.csv
id,name,price
id002,Gadget,2.00
id001,Widget,1

A text diff can report moved lines as deletions and additions. A keyed comparison matches id001 with id001 and id002 with id002, then reports zero field differences for this pair.

Values that look equal but are not, or vice versa

GridLens compares decoded field strings. Identifier 001 differs from 1, and amount 02.00 differs from 2.00. This can reveal formatting differences between systems, but may also be stricter than a numeric reconciliation needs. Quoting alone is not a field-value difference: "text" and text decode to the same value. Numeric tolerance is not implemented; normalize a separate copy deliberately if that is required.

Duplicate keys are refused, not guessed

Keyed comparison depends on each key value appearing once per file. If id001 appears twice in the same file, there is no single correct way to decide which occurrence to match against the other file. Rather than pick one arbitrarily, or silently merge them, GridLens refuses to compare and reports the duplicate so you can fix the source data. This demo page reports duplicate keys only within the sample limits listed above; the full extension applies the same rule at its own, larger limits.

Explicit headers, not guessed columns

Enable header mode only if both first records contain column names. In this mode, fields match by exact unique header names, so column order may differ. Both files need the same header names. Without header mode, fields match by position and both schemas need the same width. Choose the key column independently in each file using a one-based number. Blank or duplicate keys block matching; repeated IDs are never silently fixed.

Snapshot vs. full extension

This page is a snapshot of one feature at reduced limits, meant to show the approach quickly in a browser. It is not a replacement for the VS Code extension, which handles far larger files, more columns, the same duplicate-key and literal-value rules, plus CSV/TSV editing, column summaries and read-only XLSX viewing.

Choose the tool that fits

Other VS Code tools, including Edit CSV and Spreadsheet Viewer, handle CSV and spreadsheet workflows too. GridLens focuses on literal keyed comparison and duplicate-key checks. Numeric tolerance and fuzzy matching are not implemented.

Data & privacy

The demo has no input storage, telemetry or upload code. Clear data removes inputs and results from the page; it does not guarantee erasure from browser memory. Browsers may restore form text or retain session data; avoid sensitive data on shared devices.

Limitations

This is a reduced-limit demo of one feature. Duplicate checks inspect every accepted record; only displayed issue samples are capped. Use the extension for larger files and other tools.
